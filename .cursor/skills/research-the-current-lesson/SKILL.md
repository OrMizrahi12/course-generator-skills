# Research the current lesson

This skill is deep and narrow. One lesson. Now. All attention goes here, not to the rest of the course.

The syllabus skill already set direction. This skill makes you competent to film **this** lesson at best practice: correct material, correct operation, a real human example.

The model will want a shallow search and a smoke-test example, or will wander into the next lessons. That is the bug.

## When this runs

After the syllabus is accepted, and before ffmpeg, before writing the on-camera path, and before shipping the lesson. Every lesson, again. Do not reuse last lesson's research.

If [Real example in every lesson](sand-workflow:real-example-in-every-lesson) is about to run its gates, this skill has already finished.

## Lock the scope

Write down only:

- Lesson number and title from the accepted syllabus
- What the viewer can do after this lesson
- Audience and level already agreed for the course

Do not reopen lesson count, order, or other titles. Do not research lesson N+1 "while you are here".

## Learn the material (current, not memory)

- Read current official docs and changelog for this feature
- Look at the live Agents Window UI for this feature (where it lives, what it is called now)
- State in one sentence what the feature is, and one sentence what it is not
- Note common mistakes or outdated steps so the lesson does not teach a dead path

If you cannot find a live source, say so. Do not invent behavior from the lesson title.

## Learn to operate it

Map how a person actually does this in the current UI: where they enter, what they create, what "done" looks like.

Research and looking are off-camera. Creating the **lesson object** is not. Do not pre-create the command, skill, rule, automation, pin, or MCP that the viewer must see created. If you do a throwaway probe, reset the UI to the state before that object existed before you record.

## Choose the human example (after the research, not before)

Do not assume you already know what looks human.

1. What tools, connectors, files, and repos exist **here** and can finish on camera. Prefer a real catalog server or a real artifact over a toy.
2. Write two or three candidate human jobs where **this** feature is necessary.
3. Pick the most useful one that can still finish 0% to 100% on camera. Authentic and bounded.
4. One sentence: a person wants X because Y, and this feature is required for X.

If you can delete the feature and the task stays the same, the example is dead. Smoke tests are dead (`echo`, hello files, dummy MCP, "reply with only this").

## Best practice check

Before you leave this skill:

- Would a good teacher show this path, or a shortcut that hides how the thing is made?
- Does the example make the feature necessary?
- Can this be one complete film (creation, path, result) for a viewer who has never used it?

If any answer is no, do not proceed to recording. Fix the brief.

## Output (this lesson only)

A short brief, then stop:

- Feature, in one human sentence
- The human job (X because Y) and why the feature is required
- What "done" looks like on screen
- Sources you actually used
- Anything the viewer must see created on camera

Do not write the full click script here. Do not start ffmpeg here. Hand off to [Real example in every lesson](sand-workflow:real-example-in-every-lesson) for the 0–100% path and ship gates, then to the recording skills.

## Do not

- Rebuild or edit the syllabus
- Research other lessons in the same pass
- Pick the example first and research after to justify it
- Create the lesson object off-camera
- Start recording mid-research
